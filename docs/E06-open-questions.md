## E07 / E09 (FYI)
- `npm run smoke` prints a single `DOTTIE_SMOKE_OK {...}` line that is easy to check in CI. **DOT-098:** in CI use `npm run smoke:ci` (`scripts/smoke-run.mjs [--runs N] [--out DIR] [--timeout-ms MS]`). Each run gets a hard timeout and its full output is always kept in `DIR/runNNN.log`, also on timeout (`DOTTIE_SMOKE_RUNNER_TIMEOUT` footer). There are no retries or skips, and the runner exits 1 unless every run printed `DOTTIE_SMOKE_OK`. Upload `DIR` as a CI artifact. Inside the smoke, every approval-window wait is a named step with its own 5 s bound, and a 60 s watchdog covers everything else. A stall prints `DOTTIE_SMOKE_FAIL {"reason":"step_timeout","failedStep":…,"completedSteps":…,"partial":…,"activity":…}` and exits 1. Each closing click must produce exactly one `ApprovalResolved` (`reason:"step_assertion"` otherwise). At the end, one check compares the full ordered `ApprovalResolved` sequence of (actionId, approved), `a/true, b, c, d, f (codex), e, 9` all `false`, so count, value and actionId are pinned and a late duplicate is caught (`failedStep:"final.replySequence"`). **DOT-099:** the sequence is checked again after a 1 s settle, just before `DOTTIE_SMOKE_OK` (`final.replySequenceSettled`), so a duplicate of the last reply that arrives up to 1 s late also fails. A stray reply is blamed on the step whose action produced it (`failedStep:"after:<step>"`), never on the click whose window it landed in. A wrong reply at an expected position is still blamed on the check. F3b was closed by E01's amendment (arch 202ac23) with no code change: a forced runner timeout writes a final header `result:"fail"` (never `pass`), and a killed runner leaves only a `.partial` with `result:"incomplete"`. Both are shown in `docs/evidence/tickets/DOT-099/20261019-5ae9394/`. The evidence README rules now live at E07's `f59fd30` (`/workspace/dottie-e07`), which is identical to bfacd64. **DOT-099 follow-ups (E07 review 502ae6f, after acceptance; same ticket, no new id):**

':(exclude)docs/evidence'`, and headers carry `dirtyTreeScope:"repo, excluding docs/evidence/"`. The watchdog always names a position (`failedStep` = the running step, or `after:<last step>`). It doesn't cover app startup; the runner's 90 s timeout does (E01). Runner files follow the dottie-evidence-pack naming and carry the §4 header as their first line (`--case-id`, `--runner`); a run's `.partial` gets a provisional header (`result:"incomplete"`) before electron starts, so a killed runner still leaves a header'd log.
