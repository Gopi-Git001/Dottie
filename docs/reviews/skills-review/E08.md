# E08 Security Engineer: skills review (2026-10-18)

## Role summary
E08 owns the security baseline (DOT-008):
- env scrub
- authUrl prefix check
- redactor
- threat model TB1–TB9

E08 also owns the policy gate and approval bridge (DOT-014, with E03), removing fail-open behaviour (DOT-032, with E04), the W1-S1/S2 spikes (with E02), and the installer (DOT-050, with E06). E08 is a required reviewer on permission and auth changes (spec §7). Release blockers RB-01/02/05/07 rest mainly on E08's controls.

## Existing coverage
- dottie-policy-gate-review: non-negotiables, required RB tests
- dottie-week1-auth-go-no-go
- dottie-electron-package-check: fuses, asar, secret scan of the package
- dottie-evidence-pack: secret sweep
- gstack cso

## Gaps found
1. No threat-model method or file yet. `docs/security/` doesn't exist.
2. No redactor rule set for Dottie-specific secrets. Santa_Claus covers generic tokens only, not OAuth URL queries, userCode, email hash, Windows usernames or host IDs. No logger wire-up audit and no canary-scan procedure.
3. No auth-isolation review checklist. Several issues are scattered:
   - The desktop allowlist is broader than the CONTRACTS prefix.
   - `OPENAI_API_KEY` is a User env var on Gopi's PC.
   - Two data roots.
   - `account/chatgptAuthTokens/refresh` is in the schema.
   - RB01-U2 lists `%USERPROFILE%\.codex` but not the Dottie Codex home.
4. The E08 items in E06's open questions (CSP, protocol, permissions, signing, logging, npm audit) have no review routine.
